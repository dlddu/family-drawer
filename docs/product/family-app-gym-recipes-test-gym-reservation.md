## 0. 안전 제약 (모든 시나리오에 적용)

- **실제 예약·결제·계정 생성을 수행하지 않는다.** 공식 사이트에서 실제로 신청을 완료하는 단계는 테스트 범위 밖이다.
- 공식 URL 이 열리는지는 **"열린 URL 이 기대값과 같은가"** 로 판정한다. 열린 뒤 로그인·결제는 수행하지 않는다.
- 공식 사이트에 자동 요청을 반복해 보내는 테스트를 만들지 않는다. 외부 호출이 필요한 판정은 **스텁/모킹**으로 한다.
- 접수 기간 판정 테스트는 **기기 날짜 또는 주입된 clock** 으로 하고, 실제 접수 기간을 기다리지 않는다.

## 2. 테스트 시나리오

### 시나리오 TC-G1: 공식 URL 로만 신청이 열린다
- **사전 조건**: 센터 "부천체육관"(코드 `BCS03`) 선택됨, 네트워크 정상
- **실행 단계**: ① `STP-prep-account` 화면에서 `공식 신청 페이지 열기` 탭 ② 열린 URL 을 캡처
- **기대 결과**: 외부 브라우저(또는 시스템 인앱 브라우저)가 열리고 URL 이 `https://www.best.or.kr/fmcs/271?center=BCS03` 와 일치. 앱 내부 WebView 에서 로그인 폼을 렌더하지 않는다
- **검증 AC**: AC-G1

### 시나리오 TC-G1b: 앱은 자격증명을 받지 않는다 (부정 테스트)
- **사전 조건**: 앱의 전체 화면 목록(라우트 목록)을 확보
- **실행 단계**: ① 모든 화면의 입력 필드를 열거해 비밀번호 타입/인증번호 필드가 있는지 확인 ② 앱 로컬 저장소 키를 덤프
- **기대 결과**: 비밀번호·인증번호 입력 필드 **0개**. 로컬 저장소에 세션 쿠키·비밀번호·인증 토큰에 해당하는 키 **0개**
- **검증 AC**: AC-G1, AC-G5

### 시나리오 TC-G2: 날짜에 따라 접수 상태 라벨이 바뀐다
- **사전 조건**: 센터 기간 데이터 = 기존회원 20~25일 / 신규 26일~말일 (확인 사실 A-3-1 기준), 센터 B 는 기간 데이터 없음
- **실행 단계**: 주입 날짜를 ① 22일 ② 27일 ③ 5일 ④ 센터 B 로 각각 바꿔 센터 상세 진입
- **기대 결과**: ① `재등록 중` ② `신규접수 중` ③ `접수 전`(다음 기간 안내 포함) ④ `기간 미확인` + 공식 안내 링크. 네 경우 모두 라벨과 같은 카드 안에 **근거 날짜 범위**와 **정보 확인일**이 보인다. ④ 에서 추측 날짜를 표시하지 않는다
- **검증 AC**: AC-G2

### 시나리오 TC-G3: 미충족 조건이 CTA 전에 드러난다
- **사전 조건**: 체크리스트 초기 상태(전부 미체크), 신청 대상 나이 = 40세
- **실행 단계**: ① 준비 화면 진입 → 배너 확인 ② 4항목 전부 체크 → 배너 확인 ③ 대상 나이를 13세로 변경 → 항목 확인
- **기대 결과**: ① 경고 배너 표시, **CTA 는 활성 상태 유지** ② 배너 사라짐 ③ "법정대리인 동의" 항목이 표시됨(40세에서는 숨김)
- **검증 AC**: AC-G3

### 시나리오 TC-G4: 외국인 경로는 막힌 길로 끝나지 않는다
- **사전 조건**: 준비 화면, 센터 전화번호·현장 접수 시간 데이터 존재
- **실행 단계**: "외국인 등록 구성원" 토글 켜기
- **기대 결과**: 증빙서류·현장 확인 필요 안내 + 센터 전화번호 + 현장 접수 시간(평일 06:00~21:00 / 토·일·공휴일 09:00~16:00 형태)이 표시됨. 여정 문서의 "여정 밖 종료(현장 접수)" 와 일치
- **검증 AC**: AC-G4

### 시나리오 TC-G5: 고정 문구가 CTA 보다 먼저 읽힌다
- **사전 조건**: 준비 화면, 설정·도움말 화면
- **실행 단계**: 두 화면에서 문구 존재와 위치 확인
- **기대 결과**: 두 곳 모두에 "이 앱은 대신 신청하지 않습니다. 신청과 결제는 부천도시공사 공식 페이지에서 직접 하셔야 합니다." 가 있고, 준비 화면에서는 CTA 보다 **위**에 위치
- **검증 AC**: AC-G5

### 시나리오 TC-G6: 세 가지 결과가 모두 기록된다
- **사전 조건**: `STP-official-apply` 를 거쳐 앱으로 복귀한 상태
- **실행 단계**: 결과 기록 시트에서 ① `신청 완료` ② `대기·미정` ③ `실패(마감 등)` 를 각각 선택(3회 반복, 각 회차 새 시도로)
- **기대 결과**: 3건 모두 목록에 해당 상태로 저장되고, 각 기록에 센터·프로그램·대상자·해당 월이 포함. 화면에 "내가 기록한 값" 표기가 있다
- **검증 AC**: AC-G6

### 시나리오 TC-G6b: 기록을 건너뛰어도 흔적이 남는다
- **사전 조건**: TC-G6 과 동일
- **실행 단계**: 결과 기록 시트를 선택 없이 닫기 → 목록 확인 → 앱 재실행
- **기대 결과**: 목록에 `미기록` 배지 항목이 남고, 재실행 시 "지난번 신청은 어떻게 되었나요?" 이어하기 경로가 제공됨
- **검증 AC**: AC-G6

### 시나리오 TC-G7: 재등록 알림이 1건 예약된다
- **사전 조건**: 센터 A(기간 데이터 있음)에 `신청 완료` 기록 1건, 알림 권한 허용
- **실행 단계**: 기록 직후 예약된 알림 목록 조회
- **기대 결과**: 다음 재등록 기간 시작 **1일 전 09:00** 로 알림 1건 예약. 알림 설정 화면에 "이 기기에서만 알림이 울립니다" 한계 표기 존재
- **검증 AC**: AC-G7

### 시나리오 TC-G7b: 기간 데이터가 없으면 알림을 지어내지 않는다
- **사전 조건**: 센터 B(기간 데이터 없음)에 `신청 완료` 기록 1건
- **실행 단계**: ① 예약된 알림 수 확인 ② 날짜를 수동 입력 ③ 다시 확인. ④ 알림 권한을 거부로 바꾸고 화면 확인
- **기대 결과**: ① 0건 + 목록에 `알림 없음` 표시 ② 입력 수용 ③ 1건 예약 ④ 알림 설정 화면에 권한 거부 상태와 설정 이동 안내 표시
- **검증 AC**: AC-G7

### 시나리오 TC-G8: 오래된 정보는 오래됐다고 말한다
- **사전 조건**: 센터 상세의 요금 확인일을 ① 오늘 ② 61일 전으로 각각 주입
- **실행 단계**: 센터 상세 진입 → 요금·이용시간 영역 확인 → 출처 링크 탭
- **기대 결과**: ① `확인일 · 출처` 표시, `오래된 정보` 없음 ② `오래된 정보` 표시 추가. 두 경우 모두 출처 링크 탭 시 공식 페이지(`best.or.kr`) 로 이동
- **검증 AC**: AC-G8

### 시나리오 TC-G9: 열기 실패 시 대안이 있다
- **사전 조건**: 네트워크 차단 또는 브라우저 실행 실패 주입
- **실행 단계**: ① CTA 탭 ② 오류 배너 확인 ③ `URL 복사` 탭 ④ 클립보드 확인 ⑤ `다시 열기` 탭
- **기대 결과**: ② "공식 페이지를 열지 못했어요" 배너 ④ 클립보드 값이 `https://www.best.or.kr/fmcs/271?center=BCS03` ⑤ 재시도가 `STP-official-apply` 로 재진입
- **검증 AC**: AC-G9

### 시나리오 TC-G10: 가족 단위로 보이고 꺼낼 수 있다
- **사전 조건**: 구성원 라벨이 서로 다른 기록 2건 이상
- **실행 단계**: ① 구성원 필터 적용 ② 내보내기 실행 ③ 결과물 확인
- **기대 결과**: ① 필터가 해당 구성원 기록만 남긴다 ② 내보내기 결과에 **모든** 기록(센터·프로그램·대상자·월·상태·메모)이 포함 ③ 기기 간 자동 동기화는 보장하지 않음이 화면에 명시
- **검증 AC**: AC-G10

### 시나리오 TC-G11 ⏳: 반복 열기 실패를 사용자 신고 없이 구분한다 — **향후 검증, 지금 실행하지 않음**
- **상태**: ⏳ 이 시나리오는 **아직 실행할 수 없고 실행한 적도 없다.** 지원 OS(D-02)와 진단 맥락의 수집·전송 수단이 정해지기 전에는 판정 대상이 없다. 여기 적는 것은 **그때 무엇을 보면 통과인지**다.
- **사전 조건(향후)**: 플랫폼과 수집·전송 수단이 결정되어 있고, 테스트 기기에서 공식 페이지 열기를 실패시킬 수 있다 (네트워크 차단 또는 핸들러 차단)
- **실행 단계(향후)**: ① `STP-official-apply` 의 CTA 를 눌러 열기 실패를 만든다 ② 같은 단계에서 한 번 더 눌러 **연속 2회 실패**를 만든다 ③ 사용자 쪽에서 **아무 추가 조작도 하지 않는다**(로그 수집·화면 캡처·문의 작성 없음) ④ 개발자가 받은 진단 맥락을 확인한다
- **기대 결과(향후 판정)**:
  - ㉠ **앱 버전**, **실패한 화면·작업 단계**(`official-handoff` / `STP-official-apply`), **실패 유형**(열기 실패 / 점검·마감 / 권한 거부) 세 항목이 **서로 구분 가능**하다
  - ㉡ 두 번의 실패가 각각 **상관 ID** 로 묶여 한 시도씩 식별된다
  - ㉢ **연속 2회 실패**라는 사실이 사용자 신고 없이 드러난다
  - ㉣ 진단 맥락에 **자격증명·가족 구성원 이름·메모 본문이 없다** (가치 문서 부록 [§E-3 ③-C1](./family-app-gym-recipes-values-appendix.md#e-3-val-diagnosable-without-the-user--사용자가-설명하지-않아도-진단된다))
  - ㉤ 사용자가 추가로 한 조작이 **0회**다 (③-C2)
- **검증 AC**: AC-G11
- **지금 하지 않는 이유**: 수단을 정하는 것은 이 PRD·테스트의 몫이 아니다. 모니터링 SDK 도입이나 개인정보 수집 범위는 여기서 결정하지 않는다 (D-02·D-03).
