## 대상 사용자 (가족)

이 제품은 "두 사람이 쓴다"고 **단정하지 않는다.** 확인된 것은 가족 구성원이 복수라는 것뿐이고,
인원수·구성은 미확정이다(`open-questions.md` D-07). 대신 **역할(role)** 로 설계한다.

| 역할 | 하는 일 | 두 요구와의 관계 |
|---|---|---|
| **신청자** | 헬스장 수강신청을 실제로 하는 사람. 공식 사이트에 통합회원 계정이 있다 | 요구 ① 주 사용자 |
| **공유자** | 유튜브에서 본 요리 영상을 가족에게 공유하는 사람 (예: 엄마) | 요구 ② 입구 |
| **소비자** | 모인 레시피를 보고 요리하거나, 다른 사람의 헬스 등록 상태를 알고 싶은 사람 | 요구 ② 출구, 요구 ① 열람 |
| **대리인** | 14세 미만 구성원을 대신해 동의·신청을 하는 보호자 | 요구 ① 분기 (확인 사실 A-4-2) |

한 사람이 여러 역할을 겸할 수 있고, 한 역할에 여러 사람이 있을 수 있다. 문서는 역할 기준으로 쓴다.

**가치 ②가 특히 보는 사람**: 위 역할 중 누구든 **나이가 많은 가족 구성원**일 수 있다. 설명을 듣고 쓰는 사람이 아니라
**설명 없이 처음 열어보는 사람**을 기준으로 판단한다.

## 제품 목표

**가족이 "놓치면 다시 하기 번거로운 일"을 놓치지 않게 한다.**

구체적으로 두 가지다.

1. 부천도시공사 체육센터 헬스 등록은 **접수 기간이 월 단위로 열리고 닫힌다**(확인 A-3-1). 기간을 놓치면 한 달을 기다린다.
   → 앱은 기간·준비물·공식 경로를 제때 꺼내 준다.
2. 유튜브에서 본 요리 영상은 **공유된 순간에만 존재하고 금방 묻힌다.**
   → 앱은 공유를 받아 가족 보관함에 남기고, 요리할 때 원본을 다시 열어 준다.

## 제품 범위 (1단계)

### 범위 안

| 구분 | 내용 |
|---|---|
| 요구 ① | 센터·프로그램 정보 보기, 접수 기간 상태 표시, 사전 준비 체크리스트, **공식 신청 페이지로 보내기**, 신청 결과를 사용자가 직접 기록, 다음 재등록 알림 |
| 요구 ② | 유튜브 앱 공유 수신, 링크 정규화·중복 판정, 레시피 항목 저장(제목·메모·태그), 보관함 탐색, **원본 다시 열기**, 잘못 저장·중복 정리 |
| 공통 | 사용자가 보는 피드백 문구(성공·중복·오류·오프라인)를 PRD 에서 고정 |

### 범위 밖 (의도적 제외 — 사유 포함)

| 제외 항목 | 사유 |
|---|---|
| **자동 예약·자동 신청, 공식 사이트 자동 로그인, 계정 자격증명 저장** | 운영기관의 허가·약관 확인이 없다 (미확인 A-6-3, A-6-4). 본인인증 기반 공공 서비스에서 제3자 앱이 대행하는 것은 약관·개인정보·장애 책임 위험이 크다 → D-01 |
| **앱 안에서의 결제** | 결제는 공식 경로에서만 일어난다. 온라인 결제 수단도 미확인(A-4-6) |
| 센터 빈자리/정원 실시간 조회 | 공개 API 근거 없음(A-6-3) |
| 레시피 영상 자동 요약·재료 추출 | 1단계 목표(놓치지 않기)에 불필요. 2단계 후보 |
| 유튜브 영상 다운로드·오프라인 재생 | YouTube 약관 위반 소지 |
| 가족 계정·초대·실시간 동기화 | 인프라 미결정(D-03). 1단계는 결정 이후로 미룬다 |
| **진단 맥락의 수집·전송 수단** (상관 ID 발급 체계, 수집·집계 백엔드, 모니터링·크래시 SDK 도입, 오류율·반복 실패 자동 감지 파이프라인) | 가치 ③은 **판단 기준**이고 1단계 기능이 아니다. 어디에 보내고 어디에 쌓을지는 지원 OS(D-02)·공유 인프라(D-03) 결정 전에 정할 수 없다. 1단계 PRD 는 **수단을 정하지 않고**, 이미 있는 AC 가 만족시키는 범위(실패 유형 구분·화면 문구·출처 표기)까지만 다룬다 |

### 이 세션에서 하지 않은 일 (명시)

실제 예약·결제·계정 생성·로그인을 **수행하지 않았다.** 조사는 공개 페이지 열람까지만 했다.

## 제품 가치

최상위 가치는 **세 개**이고, **① 사용자 편의성이 최우선**이다. 아래 하위 기준은 각 가치를 판정하기 위한 것이다.

①과 ②가 부딪히면 — 예컨대 단계를 줄이려다 화면이 못 알아볼 만큼 빽빽해지면 — **②를 지키는 쪽을 고른다.**
나이 많은 가족이 못 쓰는 편의는 편의가 아니기 때문이다. 이는 ②가 ①을 **이긴다**는 뜻이 아니라,
①의 판정 기준(①-1 "핵심 행동이 끝난다")이 ②를 전제로 한다는 뜻이다.

**가치가 아니라 범위인 것**: "신청·결제는 부천도시공사 공식 사이트에서 일어난다"는 것은 가치가 아니라
**현 단계의 기능 범위**다. 자동 예약·자동 신청·앱 내 결제는 운영기관 확인(D-01) 전까지 만들지 않으며,
근거와 함께 「제품 범위 → 범위 밖」 표에 적혀 있다. **별도의 최상위 제품 가치로 세우지 않는다.**

---

### `VAL-least-effort` ① 가장 적은 손으로 끝낸다 (사용자 편의성 최우선)

- **유형**: 구체적
- **설명**: 같은 일을 하는 데 **누르는 횟수, 입력하는 글자 수, 다시 하는 횟수**를 최소로 만든다.
  특히 **실패한 뒤 처음부터 다시 입력하게 만들지 않는다** — 받은 내용·고른 값·쓴 메모는 실패해도 남아 있어야 한다.
  이 가치는 기능을 더하는 가치가 아니라 **단계를 덜어내는 가치**다.

**하위 기준**

| # | 기준 | 헬스 예시 | 유튜브 예시 |
|---|---|---|---|
| ①-1 | **필수 입력 0, 탭 3회 이내**로 핵심 행동이 끝난다 | 홈에서 상태 확인 → 신청 준비 → 공식 페이지 열기 | 공유 → 앱 선택 → 저장 (제목·메모·태그는 전부 선택 입력) |
| ①-2 | **되풀이되는 일은 앱이 기억한다.** 사용자가 달력에 적어 두지 않아도 된다 | 재등록 기간 시작 1일 전 알림, 다니는 센터·프로그램 기억 | 저장한 항목·공유자 라벨·시작 시점 기억 |
| ①-3 | **실패 뒤 재입력을 줄인다.** 받은 값은 보존하고, 막힐 조건은 들어가기 **전에** 드러낸다 | 통합회원·본인인증·대리인 동의·관외 거주를 공식 사이트 들어가기 전에 체크, 열기 실패 시 URL 복사 제공 | 잘못된 링크도 받은 원문 그대로 보존, 오프라인이면 링크만 먼저 저장하고 제목은 나중에 |
| ①-4 | **다시 찾고 다시 여는 비용도 편의에 포함**이다. "저장됐다"로 끝이 아니다 | 지난 신청 기록을 구성원별로 다시 본다 | 보던 시작 시점까지 포함해 원본을 다시 연다, 같은 영상은 중복으로 쌓지 않는다 |
| ①-5 | **가족 중 한 사람이 한 일을 다른 사람이 다시 하지 않는다** | 누가 어느 센터에 신청했는지가 가족 기록으로 남는다 | 누가 공유한 레시피인지가 남아 다시 묻지 않는다 |
| ①-6 | **찾아 들어가는 수고를 앱이 없앤다.** 주소를 외우거나 메뉴를 헤매지 않고 한 번에 목적지에 닿는다 | 센터 코드가 붙은 공식 신청 페이지를 버튼 한 번으로 연다. 열지 못하면 URL 복사라도 준다 | 보관함 항목에서 원본 영상을 보던 지점으로 바로 연다 |

**현 단계 기능 범위에서 오는 경계 (가치가 아니라 범위)**

아래 둘은 "편의성과 겨루는 상위 원칙"이 아니라 **지금 단계가 어디까지인지**다. 근거는 「제품 범위」 표에 있다.

- **①-6 의 범위**: 이 단계에서 앱이 하는 일은 공식 신청 페이지를 **여는 것**까지다. 로그인·강좌 선택·결제는 공식 사이트에서 사용자가 직접 한다.
  그래서 앱에는 통합회원 아이디·비밀번호·인증번호를 입력받는 화면이 없다. 자동 신청·자동 로그인·앱 내 결제는 **범위 밖**이다(D-01).
  이 경계가 ①을 깎지는 않는다 — **공식 페이지에 닿기까지의 수고를 최소화하는 것**(①-2·①-3·①-6)이 이 단계의 편의성이다.
- **①-5 의 범위**: 1단계는 "역할 라벨 + 내보내기"까지만 보장하고 기기 간 자동 동기화는 약속하지 않는다 (D-03).

**근거**: 확인 A-3-1(접수 기간이 월 단위로 닫힌다) · 공유는 요리 중·이동 중에 일어난다는 **가정** · B-3(제목 조회는 실패할 수 있다)

### `VAL-obvious-to-everyone` ② 설명 없이도 다음 행동이 보인다 (직관적 UX)

- **유형**: 추상적
- **설명**: 나이가 많은 가족 구성원이 **아무 설명도 듣지 않고** 처음 열어도, ㉠ 지금 무슨 상태인지 ㉡ 다음에 무엇을 누르면 되는지
  ㉢ 누른 결과가 어떻게 됐는지를 화면만 보고 안다. 판정 기준은 "익숙한 말 / 눈에 띄는 글씨와 버튼 / 다음 행동과 결과" 셋이다.

**하위 기준**

| # | 기준 | 헬스 예시 | 유튜브 예시 |
|---|---|---|---|
| ②-1 | **익숙한 말을 쓴다.** 내부 용어·영어 약어·전문어를 화면에 내보내지 않는다 | 화면 문구는 "신청"으로 쓰고, 찾기 쉽게 설명문에 "예약"을 병기한다. `videoId`·`AC`·`정규화` 같은 말은 화면에 없다 | "엄마의 레시피에 저장했어요"처럼 가족이 쓰는 말로 쓴다 |
| ②-2 | **지금 상태가 한 눈에.** 읽어서 추론하지 않고 라벨로 본다 | `신규접수 중` / `재등록 중` / `접수 전` / `접수 종료` / `기간 미확인` 중 하나 + 근거 날짜 범위 | `제목 못 불러옴` · `볼 수 없음` 배지, 필터가 걸렸으면 칩으로 보인다 |
| ②-3 | **다음 행동이 하나로 또렷하다.** 주된 버튼은 크고 하나, 나머지는 보조로 물러난다 | 준비 화면의 주 버튼은 "공식 신청 페이지 열기" 하나 | 저장 화면의 주 버튼은 "저장" 하나 |
| ②-4 | **누른 결과를 문구로 말한다.** 조용히 성공하거나 조용히 실패하지 않는다 | 결과 기록 시트가 "기록하면 다음 재등록 기간을 알려드려요"까지 말한다 | 저장됨 / 이미 있음 / 저장 못 함을 각각 다른 문구로 보여준다 |
| ②-5 | **막힌 길을 남기지 않는다.** 할 수 없는 상태에도 다음 행동이 있다 | 외국인 구성원이면 현장 확인 안내 + 센터 전화번호·현장 접수 시간 | 영상이 삭제·비공개면 `링크 수정` 과 `삭제` 두 길을 준다 |
| ②-6 | **비슷해 보이는 것을 다르게 말한다** | `접수 전`(아직)과 `기간 미확인`(모름)을 구분 | 보관함 빈 상태와 검색 결과 0건을 다른 문구로 구분 |

**제약**

- **②-C1 쉽게 보이려고 사실을 둥글게 말하지 않는다.** 모르는 값은 "기간 미확인"으로 쓰고 추측값을 채우지 않는다. 쉬움과 ③의 솔직함이 충돌하면 솔직함이 이긴다.

**근거**: 사용자 요구(나이 많은 가족도 설명 없이 사용) · A-5-3(요금·일정은 변한다)

### `VAL-diagnosable-without-the-user` ③ 사용자가 설명하지 않아도 진단된다

- **유형**: 추상적
- **설명**: 문제가 생겼을 때 **가족이 로그를 모으거나 "이게 안 돼요"를 반복 설명하지 않아도** 개발자가 재현·원인 파악에
  필요한 맥락을 얻는 것을 목표로 한다. 이상적으로는 **사용자가 문의하기 전에** 앱 쪽이 먼저 알아챈다.
  사용자가 해야 할 조작은 **최소**여야 한다.

**하위 기준 — A군: 1단계 AC 가 이미 만족시키는 것**

| # | 기준 | 헬스 예시 | 유튜브 예시 |
|---|---|---|---|
| ③-A1 | **실패를 유형으로 구분한다.** "안 돼요"가 아니라 어떤 실패인지가 화면과 기록에 남는다 | 공식 페이지 열기 실패 / 점검·마감 / 알림 권한 거부를 각각 다른 상태로 | 유튜브 링크 아님 / 영상 ID 추출 실패 / 제목 조회 실패 / 오프라인 / 영상 삭제·비공개를 각각 구분 |
| ③-A2 | **사용자가 쓴 것과 앱이 모르는 것을 섞지 않는다** | 신청 결과는 "내가 기록한 값"으로 표기한다 — 앱은 공식 사이트의 성공 여부를 모른다 | 제목이 비면 "제목 없음"으로 두고 지어내지 않는다 |
| ③-A3 | **보여준 값의 출처와 시점을 함께 남긴다** | 요금·시간마다 `확인일 · 출처`, 60일 넘으면 `오래된 정보` 표시 | 받은 원문을 버리지 않고 보존해 무엇이 들어왔는지 알 수 있게 한다 |
| ③-A4 | **실패해도 사용자 데이터를 잃지 않는다.** 재현을 위해 사용자에게 다시 해보라고 요구하지 않아도 된다 | 결과를 기록하지 않으면 `미기록` 배지로 남아 다음 실행에서 이어서 묻는다 | 저장 화면에서 이탈해도 받은 링크가 임시 보관되어 이어진다 |

**하위 기준 — B군: 기대 결과는 적되 1단계에서 구현·검증하지 않는 것 (수단 미정)**

③의 핵심은 **사용자가 로그를 모으거나 화면을 찍어 보내지 않아도 된다**는 것이다. 그래서 B군을 "지향"으로만 두지 않고
**나중에 판정할 수 있는 기대 결과**로 적는다. 아직 구현된 것도, 운영 중인 것도, 검증된 것도 아니다.

| # | 기준 | **향후 검증 가능한 기대 결과** | 연결 AC (기대 명세) |
|---|---|---|---|
| ③-B1 | 실패 한 건을 **묶음**으로 본다 | 실패 한 건에서 **앱 버전 · 실패한 화면과 작업 단계 · 실패 유형**이 서로 구분되고, 한 번의 시도가 **상관 ID** 하나로 묶여 보인다 | `AC-G11` · `AC-R11` |
| ③-B2 | 개별 실패가 아니라 **흐름**으로 본다 | 같은 단계에서 **연속 2회 이상 실패**한 사실이 **사용자 신고 없이** 드러난다 — 예: 공식 페이지 열기 반복 실패(헬스), 링크 저장 반복 실패(유튜브) | `AC-G11` · `AC-R11` |
| ③-B3 | **문의 전에 알아챈다** | ③-B2 의 반복 실패가 사용자가 말하기 전에 이상으로 다뤄진다 | 향후 — 운영 수단이 정해진 뒤 별도 AC |

> **상태: 향후 검증 대상.** `AC-G11`·`AC-R11` 은 **기대 결과를 명세한 AC**이며, 1단계에서 구현하거나 운영하지 않는다.
> 이 문서는 **수단을 정하지 않는다** — 상관 ID 체계·수집 백엔드·모니터링·크래시 SDK 도입과 개인정보 수집 범위 결정은
> 「범위 밖」 표에 있고, 지원 OS(D-02)·공유 인프라(D-03) 결정 뒤의 과제다. 이 조정으로 새로 정한 수단은 **없다.**
> 상태 추적 문서는 B군을 **"기대 명세됨 · 미구현(🟡)"** 으로 기록한다. 구현·검증된 척하지 않는다.

**제약 (진단을 이유로 해서는 안 되는 일)**

- **③-C1 진단에 불필요한 정보는 모으지 않는다.** 특히 **부천시 통합회원 아이디·비밀번호·인증번호 등 자격증명**(①-6 범위 메모와 같은 선 — 앱이 애초에 받지 않는다),
  그리고 **가족의 개인 콘텐츠**(레시피 메모 본문, 저장한 영상 제목·링크 목록, 가족 구성원 이름·라벨)는 진단 맥락에 포함하지 않는다.
  필요한 것은 "어느 화면의 어느 단계에서 어떤 유형으로 실패했는가"이며, **무엇을 요리하려 했는지는 아니다.**
- **③-C2 진단을 위해 사용자에게 조작을 요구하지 않는다.** "로그를 보내주세요", "다시 해보고 화면을 찍어주세요"가 필요하면 이 가치는 실패한 것이다.

**근거**: 사용자 요구(가족이 로그를 모으거나 오류 설명을 반복할 필요 없게) · A-4-1(본인인증 기반 공공 서비스라 자격증명 취급 위험이 크다) · B-3(제목 조회는 실패할 수 있다)

## 가치 이동 표 (v0.1 → v0.3)

v0.1 의 최상위 가치 6개는 **최상위에서 내려갔다.** 아래가 그 대응이며, 내용이 삭제된 것은 없다.
PRD·여정 문서의 `달성 가치` 는 모두 새 ID 로 바뀌었다 (AC·단계·테스트 식별자는 그대로).

| v0.1 가치 (폐기된 최상위 ID) | v0.2 에서의 자리 |
|---|---|
| `VAL-dont-miss-window` 접수 기간을 놓치지 않는다 | ①-2 (앱이 기억한다) + ②-2 (상태가 한 눈에) |
| `VAL-official-path-only` 공식 경로를 벗어나지 않는다 | **최상위 가치에서 제거** (v0.3). 「제품 범위 → 범위 밖」 표의 사실(자동 신청·자동 로그인·앱 내 결제 범위 밖, D-01)과 ①-6 의 범위 메모로 옮겼다 — 편의성과 겨루는 별도 가치가 아니다 |
| `VAL-three-tap-keep` 본 것을 세 번 안에 남긴다 | ①-1 (필수 입력 0, 탭 3회 이내) |
| `VAL-findable-later` 나중에 반드시 다시 찾는다 | ①-4 (다시 찾고 다시 여는 비용) |
| `VAL-says-what-it-did` 앱이 한 일을 숨기지 않는다 | ②-4 (결과를 문구로) + ③-A1·③-A3 (실패 유형·출처 표기) |
| `VAL-family-not-solo` 가족 단위로 쌓인다 | ①-5 (한 사람이 한 일을 다시 하지 않는다) + ①-5 의 범위 메모(1단계는 동기화 미약속, D-03) |

폐기된 6개 ID 는 **재사용하지 않는다.** 과거 커밋·PR 에 남은 참조는 이 표로 찾는다.
