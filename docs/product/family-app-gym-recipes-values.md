## 대상 사용자 (가족)

이 제품은 "두 사람이 쓴다"고 **단정하지 않는다.** 확인된 것은 가족 구성원이 복수라는 것뿐이고,
인원수·구성은 미확정이다(`open-questions.md` D-07). 대신 **역할(role)** 로 설계한다.

| 역할 | 하는 일 | 두 요구와의 관계 |
|---|---|---|
| **신청자** | 헬스장 수강신청을 실제로 하는 사람. 공식 사이트에 통합회원 계정이 있다 | 요구 ① 주 사용자 |
| **공유자** | 유튜브에서 본 요리 영상을 가족에게 공유하는 사람 (예: 엄마) | 요구 ② 입구 |
| **소비자** | 모인 레시피를 보고 요리하거나, 다른 사람의 헬스 등록 상태를 알고 싶은 사람 | 요구 ② 출구, 요구 ① 열람 |
| **대리인** | 14세 미만 구성원을 대신해 동의·신청을 하는 보호자 | 요구 ① 분기 (확인 사실 A-4-2) |

한 사람이 여러 역할을 겸할 수 있고, 한 역할에 여러 사람이 있을 수 있다. 문서는 역할 기준으로 쓴다.

## 제품 목표

**가족이 "놓치면 다시 하기 번거로운 일"을 놓치지 않게 한다.**

구체적으로 두 가지다.

1. 부천도시공사 체육센터 헬스 등록은 **접수 기간이 월 단위로 열리고 닫힌다**(확인 A-3-1). 기간을 놓치면 한 달을 기다린다.
   → 앱은 기간·준비물·공식 경로를 제때 꺼내 준다.
2. 유튜브에서 본 요리 영상은 **공유된 순간에만 존재하고 금방 묻힌다.**
   → 앱은 공유를 받아 가족 보관함에 남기고, 요리할 때 원본을 다시 열어 준다.

## 제품 범위 (1단계)

### 범위 안

| 구분 | 내용 |
|---|---|
| 요구 ① | 센터·프로그램 정보 보기, 접수 기간 상태 표시, 사전 준비 체크리스트, **공식 신청 페이지로 보내기**, 신청 결과를 사용자가 직접 기록, 다음 재등록 알림 |
| 요구 ② | 유튜브 앱 공유 수신, 링크 정규화·중복 판정, 레시피 항목 저장(제목·메모·태그), 보관함 탐색, **원본 다시 열기**, 잘못 저장·중복 정리 |
| 공통 | 사용자가 보는 피드백 문구(성공·중복·오류·오프라인)를 PRD 에서 고정 |

### 범위 밖 (의도적 제외 — 사유 포함)

| 제외 항목 | 사유 |
|---|---|
| **자동 예약·자동 신청, 공식 사이트 자동 로그인, 계정 자격증명 저장** | 운영기관의 허가·약관 확인이 없다 (미확인 A-6-3, A-6-4). 본인인증 기반 공공 서비스에서 제3자 앱이 대행하는 것은 약관·개인정보·장애 책임 위험이 크다 → D-01 |
| **앱 안에서의 결제** | 결제는 공식 경로에서만 일어난다. 온라인 결제 수단도 미확인(A-4-6) |
| 센터 빈자리/정원 실시간 조회 | 공개 API 근거 없음(A-6-3) |
| 레시피 영상 자동 요약·재료 추출 | 1단계 목표(놓치지 않기)에 불필요. 2단계 후보 |
| 유튜브 영상 다운로드·오프라인 재생 | YouTube 약관 위반 소지 |
| 가족 계정·초대·실시간 동기화 | 인프라 미결정(D-03). 1단계는 결정 이후로 미룬다 |

### 이 세션에서 하지 않은 일 (명시)

실제 예약·결제·계정 생성·로그인을 **수행하지 않았다.** 조사는 공개 페이지 열람까지만 했다.

## 제품 가치

### `VAL-dont-miss-window` 접수 기간을 놓치지 않는다
- **유형**: 구체적
- **설명**: 신청자가 "지금 신청할 수 있는 기간인가"와 "다음 기간이 언제인가"를 앱을 켠 3초 안에 알 수 있다.
  측정은 접수 기간 중 앱 진입 → 공식 경로 이동 전환율과, 재등록 알림 수신 후 신청 기록률로 한다.
- **근거**: 확인 A-3-1 (기존회원 20~25일 / 신규 26일~말일 / 개강 1일)

### `VAL-official-path-only` 공식 경로를 벗어나지 않는다
- **유형**: 추상적
- **설명**: 신청·결제처럼 되돌리기 어려운 행동은 **항상 공식 사이트에서** 일어난다.
  앱은 보조자이며, 사용자가 "이 앱이 나 대신 신청했나?"를 의심할 여지를 남기지 않는다.
  이 가치는 기능을 늘리는 가치가 아니라 **기능을 막는 가치**이고, 다른 가치와 충돌하면 이 가치가 이긴다.
- **근거**: A-6-2 ~ A-6-5

### `VAL-three-tap-keep` 본 것을 세 번 안에 남긴다
- **유형**: 구체적
- **설명**: 공유자가 유튜브 앱에서 "공유 → 이 앱 선택 → 저장"까지 **탭 3회 이내**로 끝낸다.
  입력 필수 항목은 없다(제목·메모·태그는 모두 나중에 채울 수 있다).
- **근거**: 공유는 요리 중·이동 중에 일어난다는 가정. 제목 조회가 실패해도 저장은 성립해야 한다(B-3)

### `VAL-findable-later` 나중에 반드시 다시 찾는다
- **유형**: 추상적
- **설명**: 모아둔 레시피는 **요리하려는 순간**에 쓰인다. 그래서 "보관함에 있다"로는 부족하고,
  원본 영상을 공유된 시작 시점까지 포함해 다시 열 수 있어야 한다. 끊어진 링크는 숨기지 않고 상태를 보여 준다.

### `VAL-says-what-it-did` 앱이 한 일을 숨기지 않는다
- **유형**: 추상적
- **설명**: 저장됨 / 이미 있음 / 저장 못 함 / 제목 못 가져옴 / 공식 페이지 못 열었음을 **사용자가 보는 문구로** 알린다.
  정보 화면에는 "확인일 + 출처 링크"를 함께 둔다. 조용히 실패하거나, 오래된 값을 사실처럼 보여주지 않는다.
- **근거**: A-5-3 (요금·일정은 변한다), B-3 (제목 조회는 실패할 수 있다)

### `VAL-family-not-solo` 가족 단위로 쌓인다
- **유형**: 추상적
- **설명**: 기록은 한 사람의 메모가 아니라 가족이 공유하는 기록이다. 누가 공유했는지, 누가 등록했는지가 남는다.
  단, **공유 방식(로컬/클라우드)은 미결정**이므로 1단계는 "역할 라벨 + 내보내기"까지만 보장한다 → D-03
