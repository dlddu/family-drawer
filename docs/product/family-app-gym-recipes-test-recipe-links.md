## 0. 테스트 데이터

영상 ID 는 **11자 `[A-Za-z0-9_-]`** 다. 아래 ID 는 형식 검증용 고정값이며, 실제 영상 존재 여부에 의존하는 판정은
스텁으로 대체한다(네트워크 의존 테스트를 실제 유튜브에 반복 호출하지 않는다).

| 별칭 | 값 |
|---|---|
| `ID_A` | `dQw4w9WgXcQ` |
| `ID_B` | `aBcD_eF-1234` → **12자, 잘못된 ID 예시** |
| `ID_C` | `_-9zZaA0bB1` |

**명세 자기정합성 검증 (2026-11-25 수행)**: 아래 TC-R2 12행 · TC-R4 7행 · TC-R3 중복 판정 1건을
AC-R2 규칙만으로 구현한 참조 구현에 넣어 돌렸고 **20/20 행이 기대값과 일치**했다.
즉 이 표의 기대값은 "그럴 것 같다"가 아니라 **실행으로 확인된 값**이다. 참조 구현은 명세 점검용이며 제품 코드가 아니다.

## 2. 테스트 시나리오

### 시나리오 TC-R1: 유튜브 공유에서 3탭 안에 저장된다
- **사전 조건**: 앱 설치됨, 로그인되지 않은 상태, 유튜브 앱에 임의 영상 열려 있음
- **실행 단계**: ① 유튜브에서 `공유` 탭 ② 공유 시트에서 이 앱 탭 ③ 저장 확인 화면에서 `저장` 탭
- **기대 결과**: ② 에서 앱이 전면으로 뜨고 **로그인·온보딩 화면이 끼어들지 않는다** ③ 저장 완료. 전체 탭 수 = 3
- **검증 AC**: AC-R1
- **비고**: `[OS 결정 대기]` — 수신 방식(Android `ACTION_SEND` / iOS Share Extension) 확정 후 플랫폼별 케이스 추가

### 시나리오 TC-R2: 링크 정규화 표 (데이터 주도)
- **사전 조건**: 보관함 비어 있음. 입력은 **문자열**로 주입(URL 객체가 아님)
- **실행 단계**: 아래 입력을 각각 공유 payload 로 주입하고 추출된 `videoId` · `startSeconds` · 저장된 정규 링크를 확인

| # | 입력 문자열 | 기대 videoId | 기대 start | 기대 정규 링크 |
|---|---|---|---|---|
| 1 | `https://www.youtube.com/watch?v=dQw4w9WgXcQ` | `ID_A` | null | `https://www.youtube.com/watch?v=dQw4w9WgXcQ` |
| 2 | `https://www.youtube.com/watch?v=dQw4w9WgXcQ&t=90s` | `ID_A` | 90 | 동일 |
| 3 | `https://www.youtube.com/watch?v=dQw4w9WgXcQ&list=PLabc123&index=3` | `ID_A` | null | 동일 (list·index 버림) |
| 4 | `https://youtu.be/dQw4w9WgXcQ` | `ID_A` | null | 동일 |
| 5 | `https://youtu.be/dQw4w9WgXcQ?t=90` | `ID_A` | 90 | 동일 |
| 6 | `https://youtu.be/dQw4w9WgXcQ?si=AbCdEfGhIjKlMnOp` | `ID_A` | null | 동일 (si 버림) |
| 7 | `https://m.youtube.com/watch?v=dQw4w9WgXcQ` | `ID_A` | null | 동일 |
| 8 | `https://www.youtube.com/shorts/dQw4w9WgXcQ?si=xyz` | `ID_A` | null | 동일 |
| 9 | `https://www.youtube.com/live/dQw4w9WgXcQ?si=xyz` | `ID_A` | null | 동일 |
| 10 | `초간단 김치찌개 10분 완성\nhttps://youtu.be/_-9zZaA0bB1?si=q1` | `ID_C` | null | `https://www.youtube.com/watch?v=_-9zZaA0bB1` |
| 11 | `  엄마 추천 ⟶ https://youtu.be/dQw4w9WgXcQ?t=135 이거 꼭 봐  ` | `ID_A` | 135 | `https://www.youtube.com/watch?v=dQw4w9WgXcQ` |
| 12 | `https://youtu.be/dQw4w9WgXcQ?t=1m30s` | `ID_A` | 90 | 동일 |

- **기대 결과**: 12행 전부 기대값과 일치. #10·#11 처럼 **제목·설명이 섞인 문자열에서도 링크를 찾아낸다**. #3·#6 은 부가 파라미터를 버린다
- **검증 AC**: AC-R2

### 시나리오 TC-R3: 다른 링크 형태라도 같은 영상은 중복이다
- **사전 조건**: `https://www.youtube.com/watch?v=dQw4w9WgXcQ` 로 항목 1건 저장됨 (항목 수 = 1)
- **실행 단계**: ① `https://youtu.be/dQw4w9WgXcQ?si=AbCdEfGhIjKlMnOp` 공유 ② 중복 배너 확인 ③ `기존 항목 보기` 탭 ④ 뒤로 → 다시 같은 링크 공유 → `메모만 추가` 로 "두 번째 메모" 입력
- **기대 결과**: ② "이미 보관함에 있는 영상이에요" 배너 + 두 버튼 ③ 기존 항목 상세로 이동 ④ 항목 수는 여전히 **1**, 기존 항목 메모에 "두 번째 메모"가 덧붙음
- **검증 AC**: AC-R3

### 시나리오 TC-R3b: 시작시간만 다른 중복
- **사전 조건**: TC-R3 과 동일(항목 1건, start=null)
- **실행 단계**: `https://youtu.be/dQw4w9WgXcQ?t=120` 공유
- **기대 결과**: 중복으로 판정(새 항목 생성 0). 새 시작시간 120초를 기존 항목의 "표시 구간"으로 추가하는 제안이 보인다
- **검증 AC**: AC-R3

### 시나리오 TC-R4: 잘못된 링크 두 종류를 구분한다
- **사전 조건**: 보관함 비어 있음
- **실행 단계**: 아래 입력을 각각 공유

| # | 입력 | 기대 분류 | 기대 문구 | 기대 대안 버튼 |
|---|---|---|---|---|
| 1 | `https://naver.com/recipe/123` | ① 유튜브 아님 | "유튜브 영상 링크를 찾지 못했어요" | `받은 내용 그대로 메모로 저장` |
| 2 | `오늘 저녁 뭐 먹지` (링크 없음) | ① 유튜브 아님 | 동일 | 동일 |
| 3 | `https://www.youtube.com/@somechannel` | ② ID 추출 실패 | "링크가 중간에 끊긴 것 같아요" | `원문 그대로 저장` |
| 4 | `https://www.youtube.com/results?search_query=kimchi` | ② ID 추출 실패 | 동일 | 동일 |
| 5 | `https://youtu.be/abc` (3자) | ② ID 추출 실패 | 동일 | 동일 |
| 6 | `https://youtu.be/aBcD_eF-1234` (12자, `ID_B`) | ② ID 추출 실패 | 동일 | 동일 |
| 7 | `https://youtu.be/` (ID 없음) | ② ID 추출 실패 | 동일 | 동일 |

- **기대 결과**: 7행 전부 분류·문구·버튼이 일치. **모든 경우 받은 원문이 화면에 그대로 보이고**, 대안 버튼으로 저장하면 원문이 손실 없이 보존된다. 저장 거부 시에도 원문이 사라지지 않는다
- **검증 AC**: AC-R4, AC-R7

### 시나리오 TC-R5: 그 지점부터 다시 열린다
- **사전 조건**: `ID_A`, start=90 인 항목 1건. 유튜브 앱 설치됨
- **실행 단계**: 항목 상세 → `원본 보기` 탭 → 열린 인텐트/URL 캡처
- **기대 결과**: 유튜브 앱으로 `ID_A` 가 열리고 **90초 지점부터** 시작(전달된 시작시간 파라미터 확인)
- **검증 AC**: AC-R5

### 시나리오 TC-R5b: 유튜브 앱이 없어도 열린다
- **사전 조건**: 유튜브 앱 미설치(또는 핸들러 차단), 항목 1건
- **실행 단계**: `원본 보기` 탭
- **기대 결과**: 브라우저로 열리고 "유튜브 앱이 없어서 브라우저로 열었어요" 토스트 표시
- **검증 AC**: AC-R5, AC-R7

### 시나리오 TC-R6: 볼 수 없는 영상의 메모는 지켜진다
- **사전 조건**: 존재하지 않는 videoId 로 만든 항목 1건. 제목 "엄마 김치찌개", 메모 "고추장 1T", 태그 `국물`
- **실행 단계**: ① `원본 보기` 탭 → 실패 ② 상세 화면 재확인 ③ `⋯` → `링크 수정` 으로 `https://youtu.be/dQw4w9WgXcQ` 입력 ④ `⋯` → `삭제` → 확인 모달 → 확인 → 토스트의 `되돌리기`
- **기대 결과**: ① 실패 후 "이 영상은 지금 볼 수 없어요(삭제되었거나 비공개)" 배지 ② **제목·메모·태그 전부 보존** ③ 수정된 링크가 정규화·중복 판정을 다시 통과해 항목에 반영 ④ 삭제는 확인 모달을 거치고, 되돌리기로 항목이 복구됨
- **검증 AC**: AC-R6, AC-R2, AC-R3, AC-R7

### 시나리오 TC-R7: 피드백 문구 10종 전수 확인
- **사전 조건**: 각 상황을 재현할 수 있는 스텁
- **실행 단계**: PRD §5 표의 10개 상황을 각각 재현 — 저장 성공 / 중복 / 유튜브 아님 / ID 추출 실패 / 제목 조회 실패 / 오프라인 저장 / 유튜브 앱 없음 / 영상 삭제·비공개 / 보관함 빈 상태 / 검색 0건
- **기대 결과**: 10개 모두 **표에 적힌 표시 방식(토스트·배너·오류 상태·배지·빈 화면)과 문구가 글자 그대로** 나온다. 표에 없는 임의 문구가 나오면 실패
- **검증 AC**: AC-R7

### 시나리오 TC-R8: 빈 상태와 0건을 혼동하지 않는다
- **사전 조건**: ① 보관함 항목 0개 ② 항목 3개(태그 `국물`·`반찬` 혼합)
- **실행 단계**: ① 보관함 진입 ② 항목 3개 상태에서 존재하지 않는 검색어 입력 ③ 태그 `국물` 필터 적용 ④ `필터 지우기` 탭
- **기대 결과**: ① "아직 모은 레시피가 없어요. 유튜브에서 공유해 보세요" ② "찾는 레시피가 없어요" + `필터 지우기` (①과 **다른 문구**) ③ 적용 칩 표시 + 해당 항목만 노출 ④ 전체 목록 복귀
- **검증 AC**: AC-R8, AC-R7

### 시나리오 TC-R9: 오프라인에서도 저장은 성공한다
- **사전 조건**: 네트워크 차단
- **실행 단계**: ① `https://youtu.be/dQw4w9WgXcQ` 공유 → `저장` ② 목록 확인 ③ 네트워크 복구 ④ 항목에서 `제목 다시 불러오기` 탭
- **기대 결과**: ① "링크만 먼저 저장했어요. 연결되면 제목을 채울게요" 토스트 + 저장 성공 ② 목록에 "제목 없음" 항목 존재 ④ 제목 조회 재시도가 실행됨(조회 방법 미결정이므로 **호출 발생 여부까지** 판정)
- **검증 AC**: AC-R9, AC-R7

### 시나리오 TC-R10: 누가 공유했는지로 찾을 수 있다
- **사전 조건**: 공유자 라벨이 서로 다른 항목 2건 이상(예: `엄마`, `나`)
- **실행 단계**: ① 라벨 필터 적용 ② 라벨 수정 ③ 내보내기 실행
- **기대 결과**: ① 해당 라벨 항목만 노출 ② 수정 반영 ③ 내보내기 결과에 모든 항목의 링크·제목·메모·태그·라벨 포함. 기기 간 자동 동기화를 보장하지 않음이 화면에 명시
- **검증 AC**: AC-R10

### 시나리오 TC-R11 ⏳: 반복 저장 실패를 사용자 신고 없이 구분한다 — **향후 검증, 지금 실행하지 않음**
- **상태**: ⏳ 이 시나리오는 **아직 실행할 수 없고 실행한 적도 없다.** 지원 OS(D-02)와 진단 맥락의 수집·전송 수단이 정해지기 전에는 판정 대상이 없다. 여기 적는 것은 **그때 무엇을 보면 통과인지**다.
- **사전 조건(향후)**: 플랫폼과 수집·전송 수단이 결정되어 있고, 저장 실패를 만들 수 있다 (네트워크 차단 또는 §5 오류 상태 주입)
- **실행 단계(향후)**: ① 유튜브에서 공유해 `STP-confirm-save` 로 들어와 저장을 실패시킨다 ② 같은 단계에서 한 번 더 실패시켜 **연속 2회 실패**를 만든다 ③ 사용자 쪽에서 **아무 추가 조작도 하지 않는다**(로그 수집·화면 캡처·문의 작성 없음) ④ 개발자가 받은 진단 맥락을 확인한다
- **기대 결과(향후 판정)**:
  - ㉠ **앱 버전**, **실패한 화면·작업 단계**(`save-confirm` / `STP-confirm-save`), **실패 유형**(유튜브 링크 아님 / 영상 ID 추출 실패 / 제목 조회 실패 / 오프라인 / 원본 열기 실패) 세 항목이 **서로 구분 가능**하다
  - ㉡ 두 번의 실패가 각각 **상관 ID** 로 묶여 한 시도씩 식별된다
  - ㉢ **연속 2회 실패**라는 사실이 사용자 신고 없이 드러난다
  - ㉣ 진단 맥락에 **저장한 링크·영상 제목·메모 본문·태그·공유자 라벨이 없다** (가치 문서 부록 [§E-3 ③-C1](./family-app-gym-recipes-values-appendix.md#e-3-val-diagnosable-without-the-user--사용자가-설명하지-않아도-진단된다))
  - ㉤ 사용자가 추가로 한 조작이 **0회**다 (③-C2)
- **검증 AC**: AC-R11
- **지금 하지 않는 이유**: 수단을 정하는 것은 이 PRD·테스트의 몫이 아니다. 모니터링 SDK 도입이나 개인정보 수집 범위는 여기서 결정하지 않는다 (D-02·D-03).
