# 열린 질문 / 사용자 결정 필요 항목

> 1단계(문서) 기준 · 2026-11-25
> 규칙: **근거 없이 확정하지 않는다.** 각 항목은 ①무엇을 모르는지 ②왜 지금 못 정하는지 ③정해지기 전 문서가 쓰고 있는 임시 처리 ④정하는 데 필요한 것을 적는다.
> 임시 처리는 모두 "초안"이며, 결정이 바뀌면 해당 AC 를 고친다.

---

## 🔴 제품 방향 — 사용자(또는 운영기관)만 정할 수 있음

### D-01. 자동 예약(자동 신청)을 허용할 것인가
- **모르는 것**: 부천도시공사 공식 수강신청을 앱이 자동으로 수행해도 되는지. 공식 API 가 있는지. 이용약관이 자동화를 금지하는지.
- **못 정하는 이유**: 공개 페이지에서 **공식 API 근거를 찾지 못했고**(미확인 A-6-3), **약관 본문을 확인하지 못했다**(미확인 A-6-4). robots.txt 는 `Allow: /` 지만 이는 공개 페이지 크롤링 규칙이고 **로그인 후 신청 자동화 허가가 아니다**(확인 A-6-2).
- **문서의 임시 처리**: **자동화 범위 0.** 앱은 접수 기간 알림 · 사전 준비 체크 · 공식 경로 딥링크 · 결과 수동 기록까지만 한다 (AC-G1, AC-G5).
- **정하는 데 필요한 것**: 부천도시공사(체육사업처 또는 해당 센터)에 문의해 ① 외부 앱의 자동 신청 가능 여부 ② 공개 API/제휴 경로 유무 ③ 약관상 자동화 조항을 **문서로 받기**. 허용되지 않으면 이 질문은 닫힌다.
- **결정이 바뀌면**: AC-G1·AC-G5 와 PRD §5 표, 여정 `STP-official-apply` 단계를 전부 다시 쓴다.

### D-02. 지원 OS / 플랫폼
- **모르는 것**: Android / iOS / 둘 다 / 웹 중 무엇인가. 어떤 최소 버전인가.
- **못 정하는 이유**: 요청에 플랫폼이 없었고, 가족 구성원들이 쓰는 기기도 모른다. **이 결정 없이는 요구 ②의 입구(공유 수신)를 확정할 수 없다** — Android 는 `ACTION_SEND` intent filter, iOS 는 Share Extension 으로 구현 모양이 다르다.
- **문서의 임시 처리**: AC 문장을 OS 중립으로 쓰고, 플랫폼 의존 항목에 `[OS 결정 대기]` 표시 (AC-R1, AC-R5, AC-G7, AC-G9).
- **정하는 데 필요한 것**: **가족 구성원이 실제로 쓰는 기기 목록.** (추측하면 공유 수신이 아예 동작하지 않는 플랫폼을 고를 수 있다)

### D-03. 가족 공유 인프라
- **모르는 것**: 기록을 기기 안에만 둘지(로컬), 가족 간 동기화를 할지(서버/클라우드). 한다면 무엇으로 할지.
- **못 정하는 이유**: 가족 데이터를 외부에 올리는 결정은 비용·개인정보·계정 관리를 모두 바꾼다. 근거 없이 "Firebase 쓰자"로 확정하면 되돌리기 어렵다.
- **문서의 임시 처리**: **1단계는 로컬 저장 + 내보내기.** "기기 간 자동 동기화 없음"을 화면에 명시 (AC-G10, AC-R10).
- **정하는 데 필요한 것**: 동기화가 1단계에 필요한지에 대한 사용자 판단. 필요하다면 그 다음에 수단을 고른다.

### D-04. 알림 방식
- **모르는 것**: 기기 로컬 알림만으로 충분한지, 가족 전체에게 가는 푸시가 필요한지.
- **못 정하는 이유**: 푸시는 D-03(서버)을 전제한다.
- **문서의 임시 처리**: 로컬 알림. "이 기기에서만 울립니다" 한계를 화면에 표기 (AC-G7).
- **정하는 데 필요한 것**: D-03 결정.

### D-05. 영상 제목·썸네일을 어떻게 가져올 것인가
- **모르는 것**: oEmbed / YouTube Data API(키 필요) / 다른 방법 중 무엇을 쓸지, 각 방법의 약관·할당량 제약.
- **못 정하는 이유**: 확인하지 않았다(미확인 B-2-3). 방법에 따라 API 키 관리와 네트워크 의존성이 생긴다.
- **문서의 임시 처리**: **제목 없이도 저장이 성립한다**를 기본 동작으로 둔다. 자동 조회는 선택 기능 (AC-R9). 삭제·비공개 판정도 "열기 실패 시점"으로 늦춘다 (AC-R6).
- **정하는 데 필요한 것**: 사용 방법 선택 + 약관 확인. 키가 필요하면 보관 위치 결정(비밀 값은 저장소에 커밋하지 않는다).

### D-06. 센터별 접수 기간 데이터를 어디서 가져올 것인가
- **모르는 것**: 센터별 접수 기간을 사람이 입력할지, 공식 공고를 주기적으로 읽을지. 센터 코드 전체 표(`BCS01`~)도 미확보(미확인 A-2-2).
- **못 정하는 이유**: 공식 API 가 없고(A-6-3), 센터별로 기간이 다를 수 있다(A-3-2 미확인).
- **문서의 임시 처리**: **`기간 미확인` 을 1급 상태로 설계**하고, 사용자 직접 입력 경로를 둔다 (AC-G2, AC-G7).
- **정하는 데 필요한 것**: "직접 입력으로 충분한가" 판단. 자동 수집을 원하면 D-01 과 같은 확인이 필요하다.

### D-07. 가족 구성원 수와 역할
- **모르는 것**: 가족이 몇 명인지, 누가 신청자/공유자/소비자/대리인인지. 14세 미만 구성원이 있는지.
- **못 정하는 이유**: 요청에 "두 사람이라고 단정하지 말라"고만 있었다. 인원·구성 정보는 없다.
- **문서의 임시 처리**: **역할(role) 기준**으로 설계하고, 구성원 라벨은 자유 문자열로 둔다. 고정 명단을 만들지 않는다 (가치 문서 「대상 사용자」, AC-R10).
- **정하는 데 필요한 것**: 구성원 목록 또는 "역할만으로 간다"는 확인.

### D-08. 제품 소유자 (문서 체계 위험)
- **모르는 것**: 가치를 정의·승인하는 책임자가 누구인지.
- **못 정하는 이유**: 세션에서 지정되지 않았다. product-doc-engineer 기준 **고아 가치(🔴)** 위험이며, 임의로 지정하면 책임 소재를 문서가 지어내는 것이 된다.
- **문서의 임시 처리**: 가치 문서 소유자 = `미지정`, 상태 추적에 🔴 위험으로 기록.
- **정하는 데 필요한 것**: 이름 한 줄.

## 🟡 저장소·인프라 — 주소가 오면 바로 정해짐

### D-09. 원격 저장소 주소
- **모르는 것**: 사용자가 이미 만든 저장소의 정확한 주소(owner/repo).
- **상태**: **부모가 확인 중.** 이 세션에서는 추측하지 않았고, 원격에 쓰지 않았으며 새 저장소도 만들지 않았다.
- **문서의 임시 처리**: 전체 문서를 로컬 작업 디렉터리에만 두었다. git 저장소도 초기화하지 않았다(빈 디렉터리에 평범한 파일로 보존).
- **정하는 데 필요한 것**: 주소 한 줄. 받으면 그 저장소를 clone 한 뒤 `docs/` 를 그 안에 넣는 것이 뒤 세션의 첫 작업이다 (→ `../handoff/bootstrap-requirements.md`).

### D-10. GitHub Pages 공개 여부
- **모르는 것**: mockup 을 Pages 로 공개할지, 로컬 `file://` 로만 볼지.
- **문서의 임시 처리**: mockup 은 **단일 정적 파일**로 만들어 `file://` 에서도 동작한다(요건 7 충족, 외부 의존 0건). Pages 를 켜면 `journeys/<id>/` 로 그대로 열린다.
- **정하는 데 필요한 것**: 저장소 공개 설정 결정. 가족 정보가 들어간 문서를 공개 Pages 에 올릴지 **따로 판단이 필요하다.**

## ⚪ 뒤 세션에서 정해도 되는 것 (지금 정하면 오히려 손해)

| 항목 | 이유 |
|---|---|
| 프레임워크·언어 (Flutter / React Native / Kotlin+Swift / 웹) | D-02(지원 OS)가 먼저다. OS 를 모르고 고르면 다시 고른다 |
| 로컬 DB (SQLite / 파일 / KV) | D-03 결정에 종속 |
| 테스트 러너·CI | 스택 결정 후 |
| 디자인 시스템 토큰 | mockup 은 현재 **임의 무채색 스타일**이다. 디자인 시스템이 생기면 mockup 의 `:root` 를 그 토큰으로 바꾼다 |

## 참고: 이 세션이 하지 않은 일 (의도적)

- 실제 예약·결제·계정 생성·로그인을 수행하지 않았다.
- 추측한 원격 저장소에 push 하지 않았고, 새 저장소를 만들지 않았다.
- 부모 원장 접근, 새 세션 생성·삭제, 머지·운영 배포, 비밀 값 출력, 장기 CLI 로그인을 하지 않았다.
- 앱 코드 구현·부트스트랩을 하지 않았다 (뒤 세션의 몫).
