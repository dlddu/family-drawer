### B-2. 공유 payload 의 모양

| # | 내용 | 구분 |
|---|---|---|
| B-2-1 | Android 유튜브 앱 공유는 `text/plain` 으로 **"영상 제목 + 줄바꿈 + URL"** 형태의 문자열을 보낼 수 있다 (URL 단독이 아닐 수 있다) | **가정 — 실제 기기에서 검증 필요.** 그래서 AC-R2 는 "문자열에서 URL 을 추출"하도록 쓴다 |
| B-2-2 | iOS 공유 시트가 전달하는 항목 타입(URL / text / 둘 다)과 앱이 받는 방식 | **가정 — 대상 OS가 미정이므로 검증 전** |
| B-2-3 | 영상 제목·썸네일을 가져오는 방법(oEmbed, YouTube Data API, 페이지 파싱 등)과 각 방법의 약관·키 요구 | **미확인 → 결정 필요** (`open-questions.md` D-05) |

### B-3. 설계에 미치는 영향

- payload 가 "제목+URL" 일 수 있으므로 **정규화 입력은 URL 이 아니라 문자열**로 받는다. (AC-R2)
- `si` 같은 추적 파라미터는 **같은 영상을 다른 링크로 보이게 만들기 때문에**, 중복 판정은 URL 문자열이 아니라 **videoId** 로 한다. (AC-R3)
- 제목 조회 방법이 미정이므로, **제목 없이도 저장이 성립**해야 한다. (AC-R9)

## D. 이 문서의 한계

- 모든 `[확인]` 항목은 **2026-11-25 공개 페이지 기준**이다. 공공시설 요금·일정은 월 단위로 바뀐다.
- 로그인이 필요한 화면(실제 신청 폼, 결제 단계, 약관 전문)은 **확인하지 않았다.** 이 세션에서는 계정 생성·로그인·예약·결제를 수행하지 않았다.
- 센터별 접수 일정·센터 코드 전수 조사는 하지 않았다. 1단계 문서에는 "센터별로 다르다"는 가정만 반영했다.
